## الخصوصية — كيف تُشفَّر البيانات

الموقع عامّ، لذلك **لا يظهر اسم طالب ولا رمزه نصًّا صريحًا** في أيّ ملف منشور:

- سجلّ كلّ طالب (الاسم، الرمز، الزاوية…) مشفَّر **AES-256-GCM** بمفتاح مشتقّ من رمزه
  عبر **PBKDF2-SHA256** (150,000 دورة) والملح `23222`. لا يُفكّ السجلّ إلّا لمن يملك الرمز.
- لوحة المعلّم (كلّ السجلّات + ملاحظات الحسم `flags`) كتلة واحدة مشفَّرة برمز المعلّم بالطريقة نفسها.
- معرّف البحث عن السجلّ مشتقّ أيضًا من PBKDF2، فلا توجد بصمة سريعة تُخمَّن منها الرموز.
- الزوايا والمصادر والمئشار والأوامر تبقى مكشوفة — لا أسماء فيها.
- الصفحة تحمل `<meta name="robots" content="noindex">` فلا تُفهرس.

> حدود المنظومة: رمز من 4 أرقام حماية تنظيمية لا سرّية عالية؛ من يملك وقتًا وعتادًا يستطيع
> تجربة كلّ الرموز. الغرض منع الفضول العابر وفهرسة الأسماء، وهذا يتحقّق.

## كيف أعدّل البيانات وأعيد النشر؟

1. عدّل **`data.json` الخامّ** في جذر المشروع (لا تلمس `docs/assets/data.json` — يُبنى آليًّا):
   - **تغيير زاوية طالب**: في `students` ابحث عن الطالب (بالاسم أو الرمز) وغيّر `angle` إلى رقم الزاوية الجديد، واحذف `"prov": true` إن ثُبِّتت.
   - **إضافة مصدر**: في `angles` → الشعبة → الزاوية → `sources` أضف `{"t": "الوصف — الجهة — السنة — اللغة", "u": "الرابط"}`. ولمصدر لبنك الشعبة كلّها: في `sections` → الشعبة → `bank`.
   - **تغيير رمز**: غيّر `code` للطالب (4 أرقام، غير مكرَّر) أو `teacherCode` للمعلّم.
2. انشر بأمر واحد:

```bash
npm run deploy
```

هذا يبني النسخة المشفَّرة، ويشغّل كلّ الاختبارات (136 دخولًا وغيرها — يتوقّف إن فشل أيّ اختبار)، ثمّ يرفع إلى GitHub فيُحدَّث الموقع خلال دقيقة تقريبًا.

- بناء فقط: `npm run build` · اختبارات فقط: `npm test`
- أوّل مرّة على جهاز جديد: `npm install` (يثبّت Playwright للاختبارات).
